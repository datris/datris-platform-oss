# Release Notes

## v1.3.0 — March 25, 2026

### MCP Tool Changes

**Atomic `create_pipeline`** — The `generate_schema` tool has been removed. `create_pipeline` now accepts sample data content (base64-encoded), auto-detects the schema, and creates the pipeline in one atomic call. Agents never see or modify raw pipeline config JSON. Parameters: `content`, `filename`, `pipeline`, `destination` (postgres/mongodb/qdrant/weaviate/milvus/chroma/pgvector), `table`, `database`.

**Content-based uploads** — All upload tools (`upload_data`, `profile_data`, `upload_config`) now use base64-encoded `content` + `filename` instead of `file_path`. The old `_upload` function is replaced by `_upload_content` which decodes base64, writes to temp file, uploads multipart, and cleans up.

**`upload_file` renamed to `upload_data`** — Returns structured JSON: `{ pipelineToken, message }`.

**`update_secret` tool added** — Agents can configure AI provider API keys (anthropic, openai, ollama, embedding). Scoped to AI secrets only.

**All-string schema for MCP** — `create_pipeline` generates all columns as `string` type (no AI call, just parses CSV header). Eliminates type casting errors during ingestion. New `allStrings` parameter on `/api/v1/pipeline/generate` endpoint.

### Agent Workflow Improvements

**Simplified workflow** — `check_service_health` and `update_secret` removed from required workflow (slow, only for diagnostics). Workflow is now: `list_pipelines` → `create_pipeline` → `upload_data` → `get_job_status` → query/search.

**NEVER rules** — Server instructions explicitly prohibit: AI rules for DQ, JavaScript/REST endpoint row rules, AI transformations, JavaScript/REST endpoint transformation functions, data profiling for pipeline config generation. Default pipeline = source + destination only.

**Job status detection fixed** — `get_job_status` now correctly detects status from both detail view (`state` field: begin/processing/end/error) and summary view (`status` field: processing/success/error). Returns "STILL RUNNING" or "JOB FAILED" messages to guide agent behavior.

**Empty pipeline list message** — When no pipelines exist, `list_pipelines` returns an instruction telling the agent to create one.

**Base64 padding fix** — Automatically adds missing padding to base64 strings from agents.

### Pipeline Delete — Destination Cleanup

`DELETE /api/v1/pipeline` now cleans up destination data by default (`deleteData=true`):
- PostgreSQL: `DROP TABLE IF EXISTS ... CASCADE`
- MongoDB: `collection.drop()`
- pgvector: `DROP TABLE IF EXISTS ... CASCADE`
- Qdrant: HTTP DELETE collection
- Weaviate: HTTP DELETE class
- Milvus: HTTP POST drop collection
- Chroma: HTTP DELETE collection

### Health Check Improvements

- All timeouts reduced from 5s to 2s (PostgreSQL, MongoDB, Kafka, all vector stores)
- `check_service_health` removed from required agent workflow (slow with multiple unavailable services)
- Qdrant and Milvus health checks use HTTP instead of gRPC (no channel leaks)

### Server Fixes

- **PostgreSQL NULL handling** — `COPY` command uses `NULL '.'` to handle FRED-style missing data placeholders
- **CSV empty rows** — `StreamNotifier` handles empty CSV files gracefully instead of `UnsupportedOperationException`
- **ASGI SSE fix** — Raw ASGI handler instead of Starlette endpoints (fixes `NoneType` and double-response errors)
