# Release Notes

## v1.33.0 — September 18, 2026

**Run a pipeline and get the rows back, without landing them.**

- **Scratch destination.** A new destination for when you, or an agent, want an answer now rather than a dataset: what a source returns for these ids, whether today's file passes its data quality rules, what a transformation produces. The run goes through the same preprocessing, data quality and transformation chain as any other pipeline, and instead of writing to a table the rows are held briefly so the caller can read them back. Nothing is landed, catalogued or added to the lineage graph, and the result expires after a retention window you control. Structured sources only; a scratch pipeline cannot be combined with another destination. See [Scratch](https://docs.datris.ai/destinations/scratch).
- **Reading the result.** The first rows ride on the run's status, so a small result is the whole answer with no second step. Larger results page from the run detail page's new **View result** panel, from the CLI (`datris pipeline result`, with an option to stream the whole result to a file), and from a new `get_pipeline_result` MCP tool. Paging reads the stored result; it never re-runs the source.
- **Agents know when to keep and when to scratch.** The MCP server and the in-platform Assistant now follow a keep-or-scratch rule: data to be kept, observed, queried later or refreshed on a schedule goes to a real destination; a one-off answer goes to scratch. An agent will no longer create a table just to read rows back once. Fetch-only taps target a scratch pipeline; if the rows turn out to be worth keeping, switch the pipeline's destination and the tap, its schedule and its incremental position do not move.
- **Scratch in the UI.** The pipeline wizard offers Scratch under Destination, and the Pipelines list badges scratch pipelines so they are easy to tell apart from the ones that land data.
- **Fix: editing a secret keeps the values you did not change.** Opening a secret, changing one field and saving no longer blanks the masked sensitive fields you left alone. Applies to the Secrets page and to the secrets API.
- **Fix: the destination's authoritative flag is honoured over the API.** Setting a destination as authoritative when creating or updating a pipeline over the REST API was silently ignored; it is now applied and validated the same way as in the UI.
- **Hardening.** Object-store endpoints on S3 destinations are now checked against the same network safeguards as the other outbound connections. Pipelines writing to the built-in object store can be restricted to an allowlist of buckets, and the doctor reports pipelines whose bucket override is unrestricted or outside the list. Error responses from the query and status APIs no longer include internal diagnostic detail.

**Upgrading**

Run `datris doctor --pre-upgrade` first, then `docker compose pull && docker compose up -d --force-recreate`. No configuration changes required. The bucket allowlist is off by default, so existing object-store pipelines keep working; the doctor will warn if any pipeline overrides its bucket and you have not set a list. Scratch results are held for 24 hours by default; shorten it on shared hosts, since a result holds whatever the source returned. CLI users on pip or Homebrew: upgrade to pick up `datris pipeline result`.
