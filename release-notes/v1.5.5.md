# v1.5.5 — April 8, 2026

A small follow-up to v1.5.4 focused on onboarding, tap scheduling UX, and giving trial users a path to bring their own AI key.

## UI

- **Getting Started tab** — New first-run landing page, now the default route. Replaces MCP as the initial tab so new users see an introduction before diving into the platform.
- **Docs ↗ tab** — Top-nav link to docs.datris.ai.
- **Inline cron editor on the Taps page** — Click any tap's CRON cell to open an edit modal: preset buttons (Hourly / Daily / Weekdays / Weekly / Custom), an AI prompt field ("Every weekday at 4pm"), Quartz field validation, and a human-readable description of what the expression does. Auto-refresh pauses while the modal is open.
- **Truncate-before-run toggle in the tap wizard** — Generated pipeline destinations can now be marked as full-refresh from the wizard, setting `truncateBeforeWrite: true` on the Postgres or MongoDB destination.

## Trial: Bring Your Own LLM Key

- **Configuration tab for trial users** — Trial tenants now see the same AI provider / model / API-key form as dedicated instances, with a banner explaining the benefit of bringing their own Anthropic or OpenAI key (no shared rate limits, stronger model, isolated cost).
- **Per-tenant key resolution** — Keys saved from the trial UI are written to the tenant's Vault path and automatically override the shared Datris-managed key on the next AI call. No backend changes — `DatrisEnvironment.forEnvironment` already resolves per-tenant secrets.
- **Status indicator** — Shows "Datris-managed (default)" vs "Your own {provider} key", with a Reset button to revert.

## Server Fixes

- **TapScheduler timezone** — `CronExpression` now honors the configured `dateTimezone` from `application.yaml`. Previously cron expressions were evaluated in the JVM's default timezone, so a "0 0 9 * * ?" tap could fire at the wrong local hour after the v1.5.4 timezone configurability work.

## Documentation

- New **Multi-Tenant: Per-Tenant API Key Overrides** section in [ai-configuration](/ai-configuration), documenting the resolution chain (`{env}/anthropic` or `{env}/openai` Vault secret → global `ai.aiSecretName`), the UI flow on the Configuration tab, and direct Vault provisioning for operators.
- Cross-link from the existing CodeGen multi-tenant section so the main-key and codegen-key override patterns are discoverable from each other.
- Reordered the new-release checklist so "Wait for Docker build" runs before "Update Homebrew tap".
