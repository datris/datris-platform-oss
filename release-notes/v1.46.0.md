# Release Notes

## v1.46.0 — October 8, 2026

**Strict evidence mode, a complete record of password changes, a data-flow matrix, and graceful shutdown.**

- **Strict evidence mode.** Two new switches make evidence complete instead of best effort. With `PROVENANCE_STRICT=true`, a pipeline that stamps provenance fails its run instead of loading rows it could not stamp (XML sources, which cannot be stamped, are exempt and say so in the run status). With `AUDIT_LOG_STRICT=true`, a request that must be audited is refused with a clear 503 while the audit log cannot record it, rather than pushing an older entry out of the queue; MinIO bucket drops, Kafka messages and scheduled tap runs wait the same way, and everything replays in order once the store is back. Both default to off, so nothing changes unless you ask. `datris doctor` reports the mode in effect, and the audit-log status endpoint shows whether writes are being accepted. See [Audit Log](/audit-log#strict-mode) and [Provenance](/provenance#strict-mode).
- **The audit log records every password reset and rotation.** Resetting a user's password is recorded as `reset-password` naming the account and the admin session or key that did it. A role change carries the new and previous role. When the server starts and finds an account with no password, the bootstrap rotation is recorded as `rotate-password` with the `system` actor; the password itself never enters the audit log. The first-boot `admin` seed is recorded as `create` with reason `bootstrap`. See [Recovering admin access](/user-auth#recovering-admin-access).
- **See where your data can go.** A new [Data Flows](/production/data-flows) page lists, for each kind of data Datris handles, every place it can go and the setting that changes that, with a recipe for an install with no cloud exit. Security Architecture, AI Configuration and Field Protection link to it, and the evidence claims across the docs now say when they hold.
- **Graceful shutdown.** `docker stop` now reaches the server. The server drains in-flight requests, the Kafka consumer leaves its group cleanly, queued audit entries are written, and the process exits with code 143. Previously every stop was a hard kill after ten seconds and queued audit entries were lost.
- **Honest wording.** The docs no longer say "every row" or "every action" without saying when that is true, and point to strict mode for installs that need it.

**Upgrading**

Run `docker compose pull && docker compose up -d`. Only the server image changed. The compose file adds a 30 second stop grace period for the server; refresh it (`git pull`, or re-download `docker-compose.standalone.yml`) so the shutdown flush is never cut short. No `.env` change is required.

- **Stops behave differently.** The server now shuts down gracefully on `docker stop`, `docker compose stop|down|restart` and image upgrades: exit code 143 instead of 137, shutdown lines in the log, and queued audit entries written before exit. A stop usually completes in one to three seconds. With the audit log on and the config store down, the audit flush gives up after ten seconds and reports what it could not write, so a stop can take up to about twelve seconds; the compose grace period is 30 seconds. Installs on their own compose file keep Docker's ten second default.
- **Strict mode is opt-in.** With both switches off, provenance and audit behave exactly as before. Turning `PROVENANCE_STRICT` on makes runs fail on data that cannot be stamped and refuses saves with an unknown `provenance.fields` name. Turning `AUDIT_LOG_STRICT` on makes audited writes return 503 while the audit log cannot record them.
- **Two audit action names changed.** A password reset is now `reset-password` instead of a generic `update`, and the first-boot seed is `create` with reason `bootstrap` instead of `seed-admin`. Existing rows are unchanged; update any audit queries that filtered on the old names.
- **New fields and checks.** The audit-log status endpoint gains `strict`, `unrecorded` and `acceptingWrites`; `datris doctor` gains `audit.strict` and `provenance.strict`, both ok by default; a new metric `datris_audit_unrecorded_total` counts entries strict mode could not record.
- No other configuration changes are required.
