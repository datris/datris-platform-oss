# Release Notes

## v1.33.1 — September 18, 2026

**A schedule only ever runs code that has passed a test.**

- **Test before you schedule.** A tap can carry a schedule only once the exact script that will run on it has passed a server-side test run. Saving a schedule on a script that has never been tested, or that was edited since its last test, is refused with a message that names the tap and the remedy: save the tap unscheduled, test it, then add the schedule. Changing the cadence of an already-tested tap, clearing the schedule, and editing description, tags, target pipeline or enabled state need no re-test. See [Taps](https://docs.datris.ai/taps).
- **Editing a scheduled tap never repoints the schedule at untested code.** This holds whether the script is edited by hand, by an agent over MCP, or through the AI generate, fix, review and optimize helpers, and whether the change comes through a save or a restore of an earlier version. The scheduled script keeps running as it was until the new one has been tested and the schedule re-applied.
- **The wizard handles it for you.** Saving a tap with a schedule from the wizard now saves it unscheduled, runs the test, and applies the schedule on success. If the test fails, the tap is kept without its schedule and the wizard says so; the wizard's own Test Script button previews an unsaved script and does not, by itself, satisfy the gate.
- **Existing scheduled taps are untouched.** Taps scheduled before this rule keep running and stay editable; their first schedule or script change is accepted if the tap has ever tested or run successfully.
- **Fix: the CLI works on Python 3.14.** Every command previously failed on startup with an event-loop error.
- **Fix: plain error messages from upload, generate and profile.** A failure in those operations now returns a clear message instead of a stack trace.
- **Fix: the MCP Registry listing names the right settings.** The published listing advertised configuration names the server ignores; it now matches what the server reads. A listing for the Glama directory was added.

**Upgrading**

Run `datris doctor --pre-upgrade` first, then `docker compose pull && docker compose up -d --force-recreate`. No configuration changes required. Agents that edit a scheduled tap's script must clear the schedule first, test the new script, then re-apply the schedule; the tools explain this when they refuse. CLI users on pip or Homebrew: upgrade to pick up the Python 3.14 fix.
