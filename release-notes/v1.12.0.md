# Release Notes

## v1.12.0 — July 23, 2026

**Failed scheduled runs now retry themselves — and tell you how to fix what they can't.**

- **Automatic retry for scheduled runs.** When a scheduled tap run fails on a transient error — the source briefly unreachable, a rate limit, a network blip — Datris automatically re-runs it a few times with a short delay before flagging it. Only runs that are provably safe to repeat are retried, so a retry can never duplicate data. Running a tap manually pauses its automatic retries. On by default; retry count and delay are configurable (see the [monitoring docs](https://docs.datris.ai/monitoring)).
- **AI fix suggestions, right where failures show.** When a failure persists — a scheduled run still failing after its retries, or any pipeline job failure — Datris diagnoses it and shows a one-line suggested fix directly on the failed run in Ops → Ingestion and in tap Run History. The full diagnosis and the concrete change to make are one click away. Suggestions are advisory: nothing is changed unless you apply it.
- **Agents see suggestions too.** Agents polling pipeline status get the same one-line fix suggestion for failed jobs.
- **Sign-in session fix.** With user login enabled, an expired session now ends cleanly and returns you to the login screen right away, instead of requiring a page refresh.

**Upgrading**

- Standard upgrade: `docker compose pull && docker compose up -d`. No configuration changes required.
- CLI / MCP server: version bump only, no functional changes.
