title: "New Release Checklist"
description: "Step-by-step process for releasing a new version of Datris"
---

## Prerequisites

- All changes committed and pushed to `main`
- `sbt clean assembly` passes
- `docker compose up --build` works locally
- Documentation is up to date

## 1. Update docker-compose.yml for Local Building

Comment out the `image:` lines and uncomment the `#build:` lines for the services you changed:

| Service | Line | Change |
|---------|------|--------|
| `datris` (server) | ~122-123 | `#image: datrisai/datris-server:latest` → uncomment `build: .` |
| `ui` | ~149-150 | `#image: datrisai/datris-ui:latest` → uncomment `build: ./ui` |
| `mcp-server` | ~173-174 | `#image: datrisai/datris-mcp-server:latest` → uncomment `build: ./mcp-server` |

After testing, revert these changes before committing — the committed docker-compose.yml should use `image:` so users pull from Docker Hub.

## 2. Update Version Numbers

Update the version in these files:

| File | Field |
|------|-------|
| `mcp-server/pyproject.toml` | `version = "x.y.z"` |
| `mcp-server/cli.py` | `version_option`, `clientInfo`, and `CLI:` echo (3 occurrences) |
| `server.json` | `"version"`, `"packages[0].version"`, `"packages[1].version"`, and `"packages[1].identifier"` tag (4 occurrences) |
| `build.sbt` | `version := "x.y.z"` |

## 2. Write Release Notes

1. Archive the current release notes:
   ```bash
   cp release-notes.md release-notes/v{previous}.md
   ```

2. Write new `release-notes.md` at the project root

## 3. Build the Server JAR (if server code changed)

```bash
sbt clean assembly
```

## 4. Publish MCP Server + CLI to PyPI

**Important:** This must happen before tagging (step 6), so the MCP Registry publish workflow can find the package on PyPI.

```bash
cd mcp-server
rm -rf dist/
python3 -m build
twine upload dist/*
```

Enter your PyPI API token when prompted (or use `twine upload dist/* -u __token__ -p <token>`).

Verify:
```bash
pip3 install datris-mcp-server=={x.y.z} --no-cache-dir
```

**Note:** PyPI will not accept re-uploads of the same version. If you need to fix something, bump to the next patch version.

## 5. Commit and Push

```bash
git add -A
git commit -m "v{x.y.z}: summary of changes"
git push origin main
```

## 6. Tag the Release

```bash
git tag v{x.y.z}
git push origin v{x.y.z}
```

This triggers the GitHub Actions workflow that builds and pushes Docker images to Docker Hub (`datrisai/datris-server`, `datrisai/datris-ui`, `datrisai/datris-mcp-server`).

Wait for the GitHub Actions build to complete before proceeding.

## 7. Update Homebrew Tap

Download the new tarball and get its sha256:

```bash
pip3 download datris-mcp-server=={x.y.z} --no-binary :all: --no-deps --no-cache-dir -d /tmp/datris-brew
shasum -a 256 /tmp/datris-brew/datris_mcp_server-{x.y.z}.tar.gz
```

Clone the tap repo (if not already cloned), update the formula, and push:

```bash
cd /tmp && gh repo clone datris/homebrew-tap
cd /tmp/homebrew-tap
nano Formula/datris.rb
# 1. Change the version in the URL: datris_mcp_server-{x.y.z}.tar.gz
# 2. Replace the sha256 value with the hash from the shasum command above
git commit -am "Update datris to {x.y.z}"
git push
cd /Users/toddfearn/src/datris/datris-platform-oss
```

Verify:

```bash
brew update
brew upgrade datris
datris --version
```

## 8. Wait for GitHub Actions Docker Build

The tag push in step 6 triggers the GitHub Actions workflow that builds multi-platform (amd64 + arm64) Docker images and pushes them to Docker Hub. **Wait for it to complete before proceeding.**

```bash
gh run list --repo datris/datris-platform-oss --limit 3
```

If the build was not triggered (e.g., workflow_dispatch needed), trigger it manually:

```bash
gh workflow run "Build and Push Docker Images" --repo datris/datris-platform-oss --ref v{x.y.z}
```

**Do NOT** build and push Docker images locally with `docker buildx` — this overwrites the multi-arch `:latest` tags with single-arch images, breaking `docker compose pull` on other platforms.

## 9. Deploy to Trial Droplet

```bash
ssh root@67.205.149.242

# On the Droplet:
docker pull datrisai/datris-server:latest
docker pull datrisai/datris-ui:latest
docker pull datrisai/datris-mcp-server:latest
cd /opt/datris && docker compose -f docker-compose.prod.yml up -d --force-recreate datris ui mcp-server
docker restart nginx
```

**Important:** Always restart nginx after recreating containers — it caches container IPs and will return 502 if they change.

**If containers fail to start:** Ensure `/opt/datris/.env` exists with credentials from `/data/secrets/datris.env` and `VAULT_TOKEN` from `/data/secrets/vault-token`.

## 10. Publish to MCP Registry

This is now **automated** — the `mcp-registry-publish.yml` GitHub Actions workflow runs on tag push and publishes via OIDC.

To publish manually (if the workflow fails or you need to re-publish):

```bash
cd /Users/toddfearn/src/datris/datris-platform-oss
mcp-publisher login github    # if not already logged in
mcp-publisher publish
```

Verify:

```bash
curl "https://registry.modelcontextprotocol.io/v0.1/servers?search=io.github.datris/datris"
```

Confirm `isLatest: true` on the new version.

## 11. Verify Everything

```bash
# Docker images
docker pull datrisai/datris-server:{x.y.z}
docker pull datrisai/datris-ui:{x.y.z}

# CLI via Homebrew
brew upgrade datris
datris --version

# CLI via pipx
pipx install datris-mcp-server=={x.y.z} --force
datris --version

# MCP Registry
curl -s "https://registry.modelcontextprotocol.io/v0.1/servers?search=io.github.datris/datris" | python3 -m json.tool | grep isLatest

# Trial Droplet
curl -s https://api.trial.datris.ai/api/v1/version
# Should return: {"version":"{x.y.z}","environment":"oss","multiTenant":"true"}

# Docs site (auto-deploys from main)
# Check https://docs.datris.ai
```

## Summary

| Step | What | Where |
|------|------|-------|
| 1 | Version numbers | 4 files in repo |
| 2 | Release notes | `release-notes.md` + archive |
| 3 | Server JAR | `sbt clean assembly` (if server changed) |
| 4 | PyPI | `twine upload` (before tagging!) |
| 5 | Commit + push | GitHub `main` branch |
| 6 | Tag | GitHub tag → triggers Docker Hub build + MCP Registry |
| 7 | Homebrew | Update formula sha256, push tap repo |
| 8 | Wait for Docker build | GitHub Actions builds multi-arch images — do NOT build locally |
| 9 | Trial Droplet | Pull `:latest` images, recreate containers, restart nginx |
| 10 | MCP Registry | Automated (or `mcp-publisher publish` if failed) |
| 11 | Verify | Docker, CLI, registry, trial app, docs |
