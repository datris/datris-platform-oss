## Prerequisites

- All changes committed and pushed to `main`
- `sbt clean assembly` passes
- `docker compose up --build` works locally
- Documentation is up to date

## 1. Update docker-compose.yml for Local Building

Comment out the `image:` lines and uncomment the `#build:` lines for the services you changed:

| Service | Line | Change |
|---------|------|--------|
| `datris` (server) | ~122-123 | `#image: datrisai/datris-server:latest` → uncomment `build: .` |
| `ui` | ~149-150 | `#image: datrisai/datris-ui:latest` → uncomment `build: ./ui` |
| `mcp-server` | ~173-174 | `#image: datrisai/datris-mcp-server:latest` → uncomment `build: ./mcp-server` |
| `datris-tap-runner` | ~221-222 | `#image: datrisai/datris-tap-runner:latest` → uncomment `build: ./tap-runner` |

After testing, revert these changes before committing — the committed docker-compose.yml should use `image:` so users pull from Docker Hub.

## 2. Update Version Numbers

Update the version in these files:

| File | Field |
|------|-------|
| `mcp-server/pyproject.toml` | `version = "x.y.z"` |
| `mcp-server/cli.py` | `version_option`, `clientInfo`, and `CLI:` echo (3 occurrences) |
| `server.json` | `"version"`, `"packages[0].version"`, `"packages[1].version"`, and `"packages[1].identifier"` tag (4 occurrences) |
| `build.sbt` | `version := "x.y.z"` |

## 2. Write Release Notes

1. Archive the current release notes:
   ```bash
   cp release-notes.md release-notes/v{previous}.md
   ```

2. Write new `release-notes.md` at the project root

3. Prepend a new `<Update label="v{x.y.z}" description="{Month D, YYYY}">…</Update>` block to `docs/changelog.mdx` (newest first). Keep bullets user-facing and terse; for security fixes use vague impact only (no endpoints, attack chains, or implementation symbols).

## 3. Build the Server JAR (if server code changed)

```bash
sbt clean assembly
```

## 4. Publish MCP Server + CLI to PyPI

**Important:** This must happen before tagging (step 6), so the MCP Registry publish workflow can find the package on PyPI.

```bash
cd mcp-server
rm -rf dist/
python3 -m build
twine upload dist/* -u __token__ -p <PYPI_TOKEN>
```

Replace `<PYPI_TOKEN>` with the PyPI API token (starts with `pypi-`). The `-u __token__` flag is required for token-based auth.

Verify:
```bash
pip3 install datris-mcp-server=={x.y.z} --no-cache-dir
```

**Note:** PyPI will not accept re-uploads of the same version. If you need to fix something, bump to the next patch version.

## 5. Commit and Push

```bash
git add -A
git commit -m "v{x.y.z}: summary of changes"
git push origin main
```

## 6. Tag the Release

```bash
git tag v{x.y.z}
git push origin v{x.y.z}
```

This triggers the GitHub Actions workflow that builds and pushes Docker images to Docker Hub (`datrisai/datris-server`, `datrisai/datris-ui`, `datrisai/datris-mcp-server`, `datrisai/datris-tap-runner`).

Wait for the GitHub Actions build to complete before proceeding.

## 7. Wait for GitHub Actions Docker Build

The tag push in step 6 triggers the GitHub Actions workflow that builds multi-platform (amd64 + arm64) Docker images and pushes them to Docker Hub. **Wait for it to complete before proceeding.**

```bash
gh run list --repo datris/datris-platform-oss --limit 3
```

<Warning>
**`gh run watch --exit-status` can exit 0 while the run is still in progress** — a transient network error (e.g. `failed to get annotations: connection reset by peer`) makes it return early. The multi-arch build pushes `datris-server` + `datris-ui` first and `datris-mcp-server` + `datris-tap-runner` later, so a false exit can look done while two images' `:{x.y.z}` tags still 404. Always confirm with `gh run view <id> --repo datris/datris-platform-oss --json status,conclusion` — only `status: completed` + `conclusion: success` is real — before trusting the watch.
</Warning>

If the build was not triggered (e.g., cancelled + rerun), trigger it manually. **Always pass `-f tag={x.y.z}`** — without it the workflow defaults to `tag=latest`, which pushes only `:latest` images and no `:{x.y.z}` version tags. The MCP Registry publish needs the version-tagged image to exist, so skipping this input breaks step 10.

```bash
gh workflow run "Build and Push Docker Images" --repo datris/datris-platform-oss --ref v{x.y.z} -f tag={x.y.z}
```

<Warning>
**arm64 `npm ci` under qemu is flaky.** The `datris-ui` image's arm64 build runs under qemu emulation on amd64 runners and has intermittently hung on `npm ci` (30+ min frozen) or failed with `ETIMEDOUT`. Expect to retry 1-2 times. If the build hangs for more than 25 min on the arm64 step, cancel and rerun via the `gh workflow run` command above.
</Warning>

**Do NOT** build and push Docker images locally with `docker buildx` — this overwrites the multi-arch `:latest` tags with single-arch images, breaking `docker compose pull` on other platforms.

Before moving on, verify all three `:{x.y.z}` tags landed:

```bash
for r in datris-server datris-ui datris-mcp-server datris-tap-runner; do
  curl -sS "https://hub.docker.com/v2/repositories/datrisai/$r/tags/{x.y.z}/" \
    | python3 -c "import json,sys;d=json.load(sys.stdin);print(' ',d.get('name','?'),d.get('tag_status','MISSING'))"
done
```

All three should report `active`. If any is missing, rerun step 7's manual trigger with `-f tag={x.y.z}`.

## 8. Update Homebrew Tap

Download the new tarball and get its sha256:

```bash
pip3 download datris-mcp-server=={x.y.z} --no-binary :all: --no-deps --no-cache-dir -d /tmp/datris-brew
shasum -a 256 /tmp/datris-brew/datris_mcp_server-{x.y.z}.tar.gz
```

Clone the tap repo (if not already cloned), update the formula, and push:

```bash
cd /tmp && gh repo clone datris/homebrew-tap
cd /tmp/homebrew-tap
nano Formula/datris.rb
# 1. Change the version in the URL: datris_mcp_server-{x.y.z}.tar.gz
# 2. Replace the sha256 value with the hash from the shasum command above
git commit -am "Update datris to {x.y.z}"
git push
cd /Users/toddfearn/src/datris/datris-platform-oss
```

Verify:

```bash
brew update
brew upgrade datris
datris --version
```

## 10. Publish to MCP Registry

<Warning>
**Manual step — wait for Todd.** The `mcp-publisher` CLI is tied to Todd's GitHub OIDC login and the `mcp-registry-publish.yml` workflow occasionally needs hand-holding. Pause here and let Todd run this step.
</Warning>

This is normally **automated** — the `mcp-registry-publish.yml` GitHub Actions workflow runs on tag push and publishes via OIDC.

To publish manually (if the workflow fails or you need to re-publish):

```bash
cd /Users/toddfearn/src/datris/datris-platform-oss
mcp-publisher login github    # if not already logged in
mcp-publisher publish
```

Verify:

```bash
curl "https://registry.modelcontextprotocol.io/v0.1/servers?search=io.github.datris/datris&version=latest"
```

Confirm `isLatest: true` on the new version. **Always pass `&version=latest`** — the bare `?search=` query is paginated and returns historical versions without surfacing the newest entry or its `isLatest` flag, which makes a successful publish look like it failed.

```bash

docker pull datrisai/datris-ui:{x.y.z}

# CLI via Homebrew
brew upgrade datris
datris --version

# CLI via pipx
pipx install datris-mcp-server=={x.y.z} --force
datris --version

# MCP Registry (always pass &version=latest — the bare search is paginated and hides the newest version)
curl -s "https://registry.modelcontextprotocol.io/v0.1/servers?search=io.github.datris/datris&version=latest" | python3 -m json.tool | grep isLatest
```
