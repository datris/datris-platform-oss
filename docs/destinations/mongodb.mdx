Use this destination when an agent or pipeline produces JSON documents and you want them written to MongoDB with schema validation, audit logging, and a lineage record for every run.

The MongoDB destination writes JSON documents to a MongoDB collection. It supports upserts, transactions, and two JSON input modes.

## Schema Requirement

The source schema must contain a single field named `_json` of type `string`. Each value in this field is a JSON document that will be written to the target collection.

## JSON Modes

The JSON input mode is controlled by `everyRowContainsObject` in the source `fileAttributes.jsonAttributes`:

| Value   | Description                                                                          |
|---------|--------------------------------------------------------------------------------------|
| `true`  | Each line of the file is a separate JSON document (newline-delimited JSON).          |
| `false` | The file contains a single JSON array; each element becomes a separate document.     |

The effective default depends on whether the `jsonAttributes` block is present: when `fileAttributes.jsonAttributes` is absent altogether, the loader assumes `true` (newline-delimited); when the block is present but `everyRowContainsObject` is omitted, it defaults to `false` (single JSON array). Set it explicitly to avoid surprises.

## Upsert with Compound Keys

Specify one or more fields in `keyFields` to perform an upsert instead of a plain insert. The pipeline matches existing documents by the compound key formed from these fields. If a matching document exists it is replaced; otherwise a new document is inserted.

Each key value is matched by equality: a scalar value (string, number, boolean, date, ObjectId) matches the documents holding that value, and a sub-document value matches only a stored sub-document equal to it. A key field name must not start with `$`; a load with such a key field fails with an error naming it, as does a document missing a key field.

## Allowed destinations

A MongoDB destination is a data collection in a data database. Saving or restoring a pipeline whose destination is a MongoDB system database, a `system.` collection or one of the collections in which the platform keeps its own state, or a new or changed destination in the platform's internal database, is refused with `400` `A MongoDB destination must be a data collection, and a new destination must be in a data database. Choose another database or collection name.` A run of a pipeline with such a destination fails with the same message before anything is written, and deleting it with its data deletes the pipeline but leaves that collection in place, with a warning in the response. A pipeline saved earlier whose destination is a data collection in the internal database keeps working while it keeps the same database and collection. When `mongodb.database` is the internal database, new pipelines may use its data collections.

## Truncate Before Write

Set `truncateBeforeWrite` to `true` to delete all documents from the target collection before writing. This effectively replaces the entire collection on each run.

## Transaction Support

By default (`useTransaction: true`), all write operations execute inside a MongoDB transaction. If any error occurs during the write, the transaction is aborted and no partial data is persisted. Set `useTransaction: false` to disable transactional writes.

## Configuration Example

```json
{
  "name": "events_mongodb",
  "source": { "..." : "..." },
  "destination": {
    "database": {
      "dbName": "analytics",
      "table": "events",
      "useMongoDB": true,
      "keyFields": ["event_id", "source"],
      "truncateBeforeWrite": false,
      "useTransaction": true
    }
  }
}
```

MongoDB connection credentials are configured globally in `application.yaml` via `secrets.mongoDbSecretName`. See [Configuration Reference](/configuration-reference) for Vault secret format.

### Field Reference

| Field                 | Required | Default | Description                                          |
|-----------------------|----------|---------|------------------------------------------------------|
| `dbName`              | yes      |         | Target database name: a data database, not a MongoDB system database; for a new destination, not the platform's internal database unless `mongodb.database` is that database (see [Allowed destinations](#allowed-destinations)) |
| `table`               | yes      |         | Target collection name: a data collection, not a `system.` collection |
| `useMongoDB`          | yes      | `false` | Must be `true` to enable MongoDB destination         |
| `keyFields`           | no       |         | Array of field names forming the compound upsert key (matched by equality; names must not start with `$`) |
| `truncateBeforeWrite` | no       | `false` | Delete all documents before writing                  |
| `useTransaction`      | no       | `true`  | Wrap all writes in a MongoDB transaction             |

## Querying from Datris

The Assistant (and any MCP client) can read a MongoDB destination back without leaving Datris. Queries are find-style: a filter and an optional projection, never a write. They read the data databases only.

| Tool | Purpose |
|------|---------|
| `query_mongodb` | Query a collection (`collection`, optional `filter`, `projection`, `limit`, default 20; `-1` returns every document, within a 5-minute time limit and the result-size ceiling) |
| `list_mongodb_databases`, `list_mongodb_collections` | Discover databases and collections before querying |

The REST endpoint is `POST /api/v1/query/mongodb` ([Query API](/api-reference/query-api#query-mongodb)); a key needs the `query:mongodb` capability (included in the `read-only` and `reporting` templates). The CLI equivalent is `datris query-mongo <collection> --filter '{...}' --limit 20`.

Every query has a time limit: 30 seconds, or 5 minutes with `limit: -1`, enforced on the MongoDB server. A result larger than 256 MB of JSON text (`DATRIS_QUERY_MAX_RESULT_MB`, `0` = none) is refused with a message rather than cut short, whatever the limit. Either answers `400`; page a large read with a filter and a positive `limit`. See [Query API](/api-reference/query-api#query-mongodb).

```bash
curl -X POST http://localhost:8080/api/v1/query/mongodb \
  -H "x-api-key: $DATRIS_API_KEY" -H "Content-Type: application/json" \
  -d '{"collection": "customers", "filter": {"country": "US"}, "limit": 10}'
```
